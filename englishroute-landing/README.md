# EnglishRoute: лендинг записи на бесплатную диагностику

Статический сайт без фреймворков и сборщиков: `index.html` + `styles.css` + `main.js`.
Заявки уходят в Google Таблицу через Google Apps Script, вам приходит письмо со ссылкой на WhatsApp клиента.

Адрес после деплоя: **https://englishroute-start.web.app** (отдельный сайт рядом с englishroute.web.app, существующую платформу он не трогает).

## Структура

```
englishroute-landing/
├── public/                  ← это и есть сайт (деплоится в Firebase)
│   ├── index.html           ← страница: все блоки + состояние «Спасибо» внутри
│   ├── styles.css           ← тетрадный стиль, mobile-first
│   ├── main.js              ← форма, маска телефона, UTM, отправка. В начале APPS_SCRIPT_URL
│   ├── favicon.svg, favicon-32.png, apple-touch-icon.png
│   ├── og-image.png         ← превью для WhatsApp/Instagram/Telegram (1200×630)
│   └── assets/reviews/      ← сюда скриншоты отзывов review-1.jpg … review-6.jpg
├── apps-script/Code.gs      ← приём заявок: Таблица + письмо на почту
├── tools/                   ← не деплоится: генератор картинок и автотесты
├── firebase.json            ← хостинг, target «start»
└── .firebaserc              ← проект и привязка target «start» → site englishroute-start
```

---

## Ваш чек-лист ручных шагов

1. **Развернуть Apps Script и вставить URL** в `public/main.js` (инструкция ниже).
2. **Положить скриншоты отзывов** в `public/assets/reviews/` с именами `review-1.jpg` … `review-6.jpg` (можно меньше шести).
3. **Задеплоить или передеплоить сайт:** `firebase deploy --only hosting:start` (инструкция ниже).
4. **Поставить ссылку в шапку Instagram:** `https://englishroute-start.web.app/?utm_source=instagram&utm_medium=bio`
5. Отправить себе тестовую заявку с телефона и проверить, что пришли строка в Таблице и письмо.

## 1. Подключить приём заявок (Google Apps Script)

1. Откройте [sheets.new](https://sheets.new): создастся новая Google Таблица. Назовите её, например, «EnglishRoute — заявки».
2. В меню Таблицы: **Расширения → Apps Script**.
3. Удалите всё в файле `Код.gs` и вставьте целиком содержимое `apps-script/Code.gs` из этой папки.
4. В строке `const NOTIFY_EMAIL = '';` впишите свой Gmail в кавычки, например `'you@gmail.com'`.
   Если оставить пустым, письма будут приходить на аккаунт, в котором вы создаёте скрипт.
5. Нажмите 💾 «Сохранить».
6. Выберите в списке функций сверху `testLead` и нажмите **Выполнить**.
   Google попросит разрешения: **Проверить разрешения → ваш аккаунт → Дополнительные настройки → Перейти на страницу проекта (небезопасно) → Разрешить**.
   Это нормально: вы разрешаете своему же скрипту писать в вашу Таблицу и отправлять вам письма.
   После запуска в Таблице появится лист «Заявки» с тестовой строкой, а на почту придёт письмо. Тестовую строку можно удалить.
7. Справа сверху: **Развернуть → Новое развёртывание**.
8. Нажмите ⚙️ рядом с «Выберите тип» → **Веб-приложение**.
   - Описание: `лендинг`
   - **Выполнять как: От моего имени**
   - **У кого есть доступ: Все**
9. **Развернуть** → скопируйте **URL веб-приложения** (вида `https://script.google.com/macros/s/AKfy…/exec`).
10. Откройте `public/main.js` и в самом начале замените заглушку:
    ```js
    const APPS_SCRIPT_URL = 'https://script.google.com/macros/s/AKfy…/exec';
    ```
11. Задеплойте сайт (раздел 2).

Проверка: если открыть URL веб-приложения в браузере, он покажет `{"ok":true,"service":"EnglishRoute leads"}`.

**Если потом меняете код скрипта:** Развернуть → Управление развёртываниями → ✏️ → Версия: «Новая версия» → Развернуть. Так URL останется прежним. «Новое развёртывание» создаст новый URL, и его снова придётся вставлять в `main.js`.

Пока URL не вставлен, форма не теряет заявку: она показывает кнопку «Отправить заявку в WhatsApp» с готовым текстом.

## 2. Деплой на Firebase Hosting

Деплой делается только в отдельный сайт `englishroute-start`. Существующий сайт `englishroute.web.app` не затрагивается: `--only hosting:start` выкладывает файлы только в target `start`.

```bash
npm install -g firebase-tools
```

```bash
firebase login
```

```bash
firebase projects:list
```

Найдите проект, к которому относится englishroute.web.app. В `.firebaserc` записан ID `englishroute`. Если в списке другой ID, замените `englishroute` в `.firebaserc` (в двух местах) и в командах ниже.

```bash
cd englishroute-landing
```

```bash
firebase hosting:sites:list --project englishroute
```

Если сайта `englishroute-start` в списке нет, создайте его (один раз):

```bash
firebase hosting:sites:create englishroute-start --project englishroute
```

```bash
firebase target:apply hosting start englishroute-start --project englishroute
```

```bash
firebase deploy --only hosting:start --project englishroute
```

После деплоя сайт будет на https://englishroute-start.web.app. Для передеплоя после изменений достаточно последней команды.

## 3. Отзывы

В `public/assets/reviews/` лежат пустые заглушки `review-1.jpg … review-6.jpg` (0 байт). Сайт их не показывает: пустые и отсутствующие файлы скрываются, битых картинок не будет.

- Замените заглушки реальными скриншотами переписок с теми же именами (JPG, ширина 600–900 px достаточно).
- Хватит и 1–3 скриншотов, лишние заглушки можно удалить.
- Пока нет ни одного реального скриншота, в блоке показывается рамка «Отзывы учеников — в Instagram» со ссылкой на @englishroute1.
- В `index.html` у каждого слота стоит комментарий `ЗАМЕНИТЬ НА РЕАЛЬНЫЙ СКРИНШОТ`. Текст отзывов на сайте не пишется, только скриншоты.
- Перед публикацией скройте или замажьте имена и номера на скриншотах, если ученик не давал согласия их показывать.

## 5. Проверки, которые уже сделаны

`node tools/test.js` запускает headless Chromium (нужен пакет `playwright`) и проверяет:
- вёрстку на 375, 430 и 1280 px без горизонтального скролла и JS-ошибок;
- маску телефона (8 707…, +7 707…, 7707…, 707…) и отказ для не казахстанского номера;
- ошибки обязательных полей и фокус на первом ошибочном поле;
- отправку с заглушкой fetch: состояние загрузки, `Content-Type: text/plain`, UTM из sessionStorage, экран «Спасибо, {имя}!», текст WhatsApp;
- ошибку сети и ответ `{ok:false}`: понятное сообщение, кнопка WhatsApp с данными заявки, данные формы не теряются;
- ограничение «не чаще раза в 30 секунд», honeypot;
- отзывы: пустые заглушки → рамка Instagram, реальный файл → сетка;
- что все ссылки wa.me ведут на 77072714655 и номер нигде не перепутан.

Lighthouse (мобильный, локально): Performance 98, Accessibility 100, Best Practices 100, SEO 100.

`node tools/render-images.js` заново генерирует `og-image.png` и PNG-иконки из `tools/og.html` и `public/favicon.svg`.

## Решения, которые я принял

1. **Деплой не делал.** Firebase CLI в среде разработки не авторизован (`firebase login` не выполнен), поэтому подготовлены `firebase.json` и `.firebaserc`, а команды описаны выше. ID проекта предположил `englishroute`, потому что сайт по умолчанию называется так же, как проект. Сверьте с `firebase projects:list`.
2. **Сайт лежит в `public/`.** Так в хостинг не попадают `README`, `apps-script/` и `tools/`.
3. **Шрифты:** Caveat (рукописные заголовки и пометки) + Manrope (текст), оба с кириллицей. Загружаются неблокирующе с `display=swap`.
4. **Только светлая тема:** тетрадный лист задуман светлым, тёмный режим не делал.
5. **Цены на TOEFL и бизнес-английский не указаны**, их не было в фактах. На сайте написано: «Стоимость занятий по TOEFL и бизнес-английскому уточню на диагностике».
6. **Текст WhatsApp при ошибке отправки** расширен: имя, кто занимается, цель, формат и время. Так заявка дойдёт целиком, даже если Таблица недоступна. После успешной отправки используется ваш текст дословно.
7. **`NOTIFY_EMAIL` оставлен пустым:** почту не стал зашивать в код, который лежит в репозитории. Пустое значение = письма на аккаунт, от имени которого развёрнут скрипт. Можно вписать адрес явно.
8. **Защита заявок на стороне скрипта:** honeypot; повтор с одного номера чаще раза в 30 секунд не записывается; значения, начинающиеся с `= + - @`, экранируются, чтобы Таблица не приняла их за формулы (поэтому номер в ячейке выглядит как `'+7 (707) …`, апостроф не отображается).
9. **Ограничение 30 секунд на сайте** хранится в localStorage, поэтому перезагрузка страницы его не обходит. UTM и referrer, как и просили, лежат в sessionStorage. Всё обёрнуто в try/catch.
10. **Валидация номера:** принимается любой номер вида +7 7XX XXX-XX-XX (10 цифр после +7, первая 7). Коды операторов отдельно не проверяю, чтобы не отсечь реальные номера.
11. **Липкая кнопка на мобильном** прячется, пока на экране видна кнопка из первого экрана или сама форма, чтобы не закрывать поля. После отправки убирается.
12. **Поля `page_url` и `timestamp`** отправляются, но в Таблицу не пишутся: столбцы взяты строго по вашему списку. Адрес страницы есть в письме, в столбце «Дата» стоит время получения заявки сервером.
13. **Формулировки, которые я вывел из фактов** (проверьте, согласны ли): «диагностика ни к чему не обязывает»; «место встречи обсудим при записи»; «сдавал сам — знаю формат изнутри» на карточке IELTS; «Все четыре секции экзамена» в цене IELTS; в карточке «Заговорить свободно» упомянут бизнес-английский. Секцию IELTS (Academic или General) не указывал, этого не было в фактах.
14. **OG-картинка** сгенерирована (`public/og-image.png`, 1200×630) в тетрадном стиле с баллами IELTS. Иконка: буква E в клетку с красной чертой.
15. **Адрес в canonical, Open Graph и JSON-LD:** `https://englishroute-start.web.app/`. Если подключите свой домен, замените его в `index.html` (поиск по `englishroute-start`).
16. **Ссылка «Написать в WhatsApp» на первом экране** открывает чат с текстом «Здравствуйте! Хочу записаться на бесплатную диагностику.».
17. **Отзывы:** пустые файлы-заглушки положил, как просили. Скрипт проверяет, какие картинки реально открываются, и показывает только их.
